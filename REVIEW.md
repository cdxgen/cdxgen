# Review instructions for cdxgen

The project conventions below apply to every review. A change that breaks one
of them is a finding.

@AGENTS.md

## What Important means here

Mark a finding Important when the change would do one of these:

- Produce an invalid CycloneDX document, a purl that `@cdxgen/cdx-purl` would
  reject, or a purl on a `cryptographic-asset` component.
- Copy a secret, token, raw environment value, full command line, URL query
  string or URL credentials into a BOM property, annotation, evidence object
  or service.
- Import across the layers in `contrib/check-boundaries.js`, or import
  `lib/cli/index.js` from a lower layer.
- Call `spawnSync`, `execSync`, `existsSync`, `mkdirSync`, `fetch`, `undici`
  or `http` directly in library code instead of the safe wrappers or
  `cdxgenAgent`.
- Read `process.env` or `process.argv` inside `lib/` instead of
  `readEnvironmentVariable` or the `options` object.
- Put logic that must run once per BOM inside `buildBomNSData`.
- Add a `cdx:` property that `docs/CUSTOM_PROPERTIES.md` does not describe.
- Pass a git ref from a repository, manifest or remote to `git` without
  `isSafeGitRefName()`.
- Add a regular expression with nested quantifiers or overlapping
  alternations over untrusted text.
- Assert on a hard-coded POSIX path in a test that also runs on Windows.

Style, naming and refactoring suggestions are Nit at most.

## Cap the nits

Report at most five Nits per review.

## Do not report

- Anything Biome already enforces: formatting, import order, unused
  variables.
- Files under `types/`. They are generated by `pnpm run gen-types`.
- Lockfiles, and the expected BOMs under `test/repotests/*/expected/`.
- Fixture files under `test/data/` that are deliberately malformed or
  unusual.

## Always check

- A new or changed exported function has JSDoc, and the pull request
  regenerated `types/` with it.
- A new emitted property has a test that shows no secret reaches the BOM.
- A change to `data/queries*.json` keeps the shared tables aligned across
  `queries.json`, `queries-win.json` and `queries-darwin.json`.
- Commit messages, comments and documentation follow the writing rules in
  `AGENTS.md`: no em-dashes, no emojis, and comments that describe the code
  as it is rather than how it came to be written.

## Evidence

A claim about how existing code behaves needs a `file:line` citation from
the source, not an inference from a function or variable name.
